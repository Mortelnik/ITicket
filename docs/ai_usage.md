# Использование ИИ-ассистентов

Ассистент (Perplexity Computer) использовался при подготовке исходной версии проекта. Ниже —
честный журнал: что делал ассистент, какие ошибки он нашёл и исправил, и что
обязана проверить команда перед сдачей.

## Для чего применялся ассистент

| Задача | Что сгенерировано ассистентом |
|---|---|
| Поиск и проверка данных | найдено зеркало Kaggle-датасета v10, проверены sha256, размер, колонки |
| Каркас кода | структура репозитория, модули data/features/experiments/train/predict/api, тесты |
| Эксперименты | конфигурации 4 моделей, код честной схемы сравнения (val/test) |
| Документация | README, architecture, test_plan, deployment_monitoring, отчёт |
| Веб-демо и тюнинг | HTML-страница чата и GridSearchCV добавлены по итогам сравнения с проектом коллег (ai_ticket_classifier) |

## Ошибки, найденные и исправленные ассистентом в этой работе

Ассистент не только генерировал код, но и находил собственные ошибки —
пример реальной итерации «генерация → проверка → исправление»:

1. **Ошибка счётчиков в /metrics:** `Counter.__getitem__` возвращает 0 для
   отсутствующих ключей, из-за чего `dict(0)` падал с TypeError. Исправлено:
   счётчики вынесены в отдельные структуры.
2. **Модель не загружалась в тестах:** устаревший `on_event("startup")`
   не срабатывал в TestClient. Исправлено: переход на lifespan + контекстный
   менеджер.
3. **Слишком малая тестовая фикстура:** стратифицированный split падал на
   фикстуре с одним примером на класс. Исправлено: два примера на класс.
4. **Наложения на слайде архитектуры:** подписи перекрывали текст, у блоков
   был некорректный цвет. Исправлено после визуальной проверки рендера.

Заимствования у проекта коллег (указано честно): идея веб-демо с имитацией
чата (реализация наша — своя страница под наш контракт API) и подход
GridSearchCV-подбора C для LinearSVC (схема честности наша: cv только на
train, выбор по val, тест один раз).

## Что команда ОБЯЗАНА сделать перед сдачей (не сделано ассистентом)

1. Прогнать `uv sync --locked && uv run pytest -q` и сверить метрики
   с `experiments/results.csv`.
2. Провести код-ревью: вычеркнуть формулировки, с которыми команда не согласна.
3. Заполнить имена участников и их фактический вклад в README и отчёте.
4. Прочитать speech.md и questions.md, отрепетировать пятиминутное выступление.
5. Собрать Docker-образ (Dockerfile написан, сборка не выполнялась) и повторить
   smoke-тест в контейнере.
6. Опубликовать репозиторий и дать ссылку с доступом преподавателю.

## Улучшения с Codex, 13 ноября 2026 года

Ассистент прочитал требования задания и исходники, воспроизвёл одинаковые
ответы на русском и внёс исправления в инференс, API, демо, тесты, Docker,
CI и техническую документацию. Презентация и итоговый отчёт остаются за
командой; существующие файлы этих материалов не редактировались.

Что сделано и проверено ассистентом:

- Четыре русских обращения превращались в нулевые TF-IDF-векторы и получали
  Technical Support. Добавлены отказы для кириллицы и нулевых признаков.
- Исправлены счётчики необработанных HTTP 500, введены метрики отказов и p95,
  ограничения длины полей и поддержка обращения только с subject.
- Добавлены регрессионные проверки сохранённого артефакта на разных темах и
  отдельные примеры вне обучающей фикстуры. Финальная проверка: 46 автотестов прошли.
- Проверен живой локальный uvicorn через scripts/smoke_api.py: три очереди,
  четыре отказа, health/ready и счётчики.
- Проверены SHA256, схема, сохранённые split и совпадения текстов. Найдена
  одна нормализованная пара train/test; риск отражён в data_validation.json.
- Повторная оценка фиксированного артефакта подтвердила test macro-F1 0.6185,
  EN 0.7019, DE 0.4922 (artifact_validation.json). Новое обучение не проводилось.
- Dockerfile дополнен непривилегированным пользователем, фиксированной
  версией uv и .dockerignore; в CI добавлены сборка/запуск и HTTP-проверка.
  Docker Engine локально недоступен; успешный контейнерный запуск и удалённый
  CI ассистентом не подтверждены.

Во время реализации первая версия проверки признаков обнаружила ещё одну
проблему: CombinedTfidf не сообщал sklearn о состоянии обучения, и выделение
преобразующей части pipeline приводило к NotFittedError. Исправлена проверка
обученности вложенных векторизаторов; проверки совпадения с исходным pipeline
теперь проходят для LogReg, LinearSVC и GridSearchCV без переобучения артефакта.

Выполнение ассистентом тестов не является проверкой командой. Перед сдачей
участники должны сами повторить запуск, проверить спорные формулировки,
подтвердить роли и вклад, объяснить код и ограничения. Не заявляйте о
командной проверке, пока она не выполнена.
