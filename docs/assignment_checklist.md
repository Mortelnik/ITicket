# Соответствие заданию: сервис классификации обращений

Оценка по тексту задания, предоставленному командой; состояние на 13.11.2026.
Это инженерная самооценка, а не официальная оценка преподавателя: балльная
рубрика в задании не задана. Итоговый отчёт и презентацию готовит команда.

## Общая оценка

Техническая часть соответствует основной цели: есть сквозной учебный кейс
от бизнес-задачи и данных до экспериментов, API, тестирования, запуска и
плана мониторинга. Полноценный production и облачное развёртывание заданием
не требуются. Условная оценка инженерной части — **8/10**. До готовой сдачи
ещё нужны финальные материалы, фактические роли и проверка командой.

Кейс адаптирован к IT-поддержке с 10 очередями EN/DE. Примеры «доступ к курсу»
в формулировке задания иллюстративны: такой очереди в выбранном датасете нет.
Это нужно прямо сказать на защите. Если команда хочет именно образовательную
поддержку или русский язык, потребуются другие размеченные данные и новое
обучение — текущая модель не покрывает такой продуктовый запрос.

## Эксперименты и выводы для защиты

Все конфигурации обучались на одних train/val/test: 20 010 / 4 288 / 4 289.
Выбор сделан по validation macro-F1, гиперпараметр C подбирался на train (CV=3).
Текущая проверка повторно оценивает уже выбранный артефакт, без новых настроек.

| Вариант | val macro-F1 | Вывод |
|---|---:|---|
| Dummy most_frequent | 0.0453 | Предсказание самой частой очереди непригодно для редких классов |
| Слова TF-IDF + LogReg | 0.4689 | Текстовый сигнал заметно лучше константной модели |
| Слова + символы + LogReg | 0.4909 | Символьные признаки улучшают результат при той же семье классификатора |
| Слова + символы + LinearSVC | 0.6043 | Эта модель существенно лучше LogReg на тех же признаках |
| LinearSVC + подбор C | 0.6188 | Лучший результат на val; артефакт использует C=10 |

Test выбранного артефакта: macro-F1 **0.6185**, weighted-F1 **0.6220**,
accuracy **0.6228**; EN **0.7019**, DE **0.4922**. Macro-F1 не означает
«61,85% обращений классифицированы правильно»: долю правильных ответов
измеряет accuracy. Качество на реальных обращениях неизвестно.

Часть ошибок закономерна: Technical / Product / IT Support пересекаются по
смыслу; ошибки нужно разбирать по матрице, а не обещать идеальную маршрутизацию.
Исходные материалы экспериментов и модель не перезаписывались улучшениями.

## Что подтверждено этой проверкой

- 46 автотестов прошли; сохранённый артефакт различает три контрольные темы.
- Живой локальный HTTP-сервис прошёл smoke_api.py.
- SHA256 данных совпал с manifest.json, сохранённые индексы покрывают все строки
  ровно один раз; точных текстовых пересечений нет.
- Одна пара train/test совпала после lower/whitespace; семантические повторы
  аудит не исключает. Результат записан в experiments/data_validation.json.
- Повторная проверка test совпала с метаданными модели. Новая политика API
  не отклоняет test по языку/признакам; 2 строки не проходят лимит длины,
  4 287 из 4 289 допустимы для API. Офлайн-метрика и покрытие разделены.
- Docker Engine недоступен: сборка и удалённый CI не объявляются пройденными.

## Что сделать команде перед сдачей

1. Самостоятельно повторить команды README и показать три разные очереди,
   отказ на русском и /metrics. Подтвердить Docker через CI или локально;
   если он недоступен, честный локальный маршрут разрешён заданием.
2. Заполнить реальные роли и вклад трёх участников в README.
3. Написать отчёт 5–7 страниц по пунктам задания и презентацию 10–15 слайдов;
   перенести актуальные числа, различать реализованное и запланированное.
4. В разделе ИИ указать, что сделал ассистент, какие ошибки нашёл, что команда
   сама проверила и исправила. Старые записи журнала не считать доказательством.
5. Проверить доступ преподавателя к репозиторию и материалам, отрепетировать
   5 минут выступления и ответы на вопросы в течение 2 минут.

## Ближайший шаг развития

Собрать небольшую обезличенную выборку реальных обращений целевого продукта,
согласовать определения очередей и ручную обработку спорных тем. Затем
исключить нормализованные повторы до split, переобучить модели и оценить
качество по очередям и языкам. Русский язык добавлять только с данными и
отдельной оценкой, а порог уверенности — после калибровки. Для текущей защиты
достаточно честно показать существующий прототип и эти границы.
