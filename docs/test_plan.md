# Тест-план и результаты проверки

Проверка улучшений: 13 ноября 2026 года. Презентация и итоговый отчёт
не входят в эту проверку.

## Данные

`uv run python scripts/check_data.py --output experiments/data_validation.json`

Проверяются SHA256 и число строк по manifest.json, обязательные колонки,
непустые queue/language, пропуски текстов, покрытие и непересечение сохранённых
индексов, совпадения текстов между выборками.

Проверенный датасет: 28 587 строк, EN 16 338, DE 12 249. В subject отсутствуют
3 838 значений; они заменяются пустой строкой при объединении с body.
Точных совпадений между train/val/test нет. Одна пара train/test совпадает
после нормализации регистра и пробелов (2 строки): это остаточный риск
утечки и небольшого завышения метрик, а не доказательство полного отсутствия
дубликатов. Семантические near-duplicates этим аудитом не исключаются.
Сохранённые split и модель не менялись.

Ошибки схемы, пустые queue/language, неверный SHA256, пересекающиеся индексы
и точные межвыборочные дубликаты останавливают проверку. Нормализованная
пара отражена как предупреждение. Предупреждения load_dataset теперь видны,
а не молча отбрасываются.

## Автотесты

`uv run pytest -q`

В среде проверки: **46 passed**, одно предупреждение зависимости о переходе
TestClient с httpx на httpx2. Зависимости в рамках этих улучшений не обновлялись.

| Область | Что проверяется |
|---|---|
| Данные | схема, пропуски и пустые метки, предупреждения, разбиение |
| Модели | обучение пяти конфигураций, baseline, сохранение/загрузка |
| Обобщение | отдельные примеры EN/DE вне обучающей фикстуры, без имени класса в subject |
| Инференс | совпадение с исходным pipeline, GridSearchCV, вероятности для LogReg, пустой текст |
| Артефакт | три контрольных обращения дают IT Support, Billing and Payments, Returns and Exchanges |
| Границы API | отсутствующие и пустые поля, только subject, пределы длины и превышение |
| Неизвестный текст | кириллица, смешанный текст с VPN, emoji без признаков — 422 без очереди |
| Готовность | 503 без модели, сброс состояния после неудачной перезагрузки |
| Метрики | успешные предсказания, отказы, 4xx, необработанные RuntimeError и ValueError как 500, задержка |
| Демо | доступность страницы и использование /predict |

Контрольные обращения — регрессионные проверки интеграции, а не независимая
оценка точности. Отдельная синтетическая фикстура тоже не заменяет test датасета.

## Проверка сохранённого артефакта

`uv run python scripts/evaluate_model.py --output experiments/artifact_validation.json`

Повторная оценка фиксированного артефакта на 4 289 test-строках подтвердила
метаданные: macro-F1 0.6185, weighted-F1 0.6220, accuracy 0.6228.
EN macro-F1 0.7019, DE 0.4922. Это проверка артефакта без подбора параметров
по test. Из-за ограничения длины 2 test-обращения API отклонит;
текстовая политика не отклоняет ни одного test-обращения.
Метрика на всех строках и покрытие API записаны раздельно.

## Найденные и исправленные проблемы

1. Разные русские обращения давали Technical Support, потому что признаки
   равнялись нулю. Теперь кириллица и нулевой вектор отклоняются без очереди.
   Наличие латинского слова VPN не делает русский текст допустимым.
2. Необработанные исключения давали HTTP 500 без роста errors_5xx. Теперь
   счётчик учитывает и такие ошибки; внутренняя ValueError не маскируется под 422.
3. Запрос только с subject раньше отклонялся обязательным body, хотя логика
   разрешала одно поле. Теперь контракт и поведение согласованы.
4. Тесты сохранённой модели проверяли только наличие ключа queue. Теперь
   константная модель провалит проверку трёх различных тем.
5. CombinedTfidf не сообщал sklearn о своей обученности. Добавлена проверка
   вложенных векторизаторов, совместимая с уже сохранённым артефактом.

## Проверка работающего сервера

`uv run python scripts/smoke_api.py --url http://127.0.0.1:8000`

Выполнена на локальном uvicorn: health/ready, три очереди, четыре отказа
(пустой вход, кириллица, emoji, слишком длинный текст), счётчики и p95.
Тест запускается автоматически и после запуска контейнера в CI.

## Оставшиеся ограничения проверки

- Нет нагрузочного испытания, SLA и профиля ресурсов.
- Нет реальных обращений и независимой производственной разметки.
- Нет автоматического детектора дрейфа или отправки алертов.
- Иные языки на латинице могут получить некорректную очередь.
- Следующая итерация данных должна исключить нормализованные дубликаты
  до split и заново обучить/оценить модели; текущие результаты не переписаны.
