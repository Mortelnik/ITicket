## 2. Найденная проблема (валидация данных)

**Пропуски в `subject`: 3 838 из 28 587 строк (13.4%).** Тема обращения
отсутствует у каждого седьмого тикета. Решение: `subject` не отбрасывается и
не интерполируется — при объединении полей пропуск заменяется пустой строкой,
модель работает по полному тексту `body`. Риск: часть сигнала теряется,
качество для тикетов без темы ниже. Отдельно замерять не стали — фиксированная
замена уже покрыта тестом `test_combine_text_fills_missing_subject`.

**Вторая проблема (найдена на инференсе):** модель систематически хуже работает
на немецких текстах — test macro-F1 0.67 (EN) против 0.49 (DE)
(`experiments/best_by_language.json`). Причина: словный TF-IDF почти не делит
лексику между языками, а классов-примеров на DE меньше. Это ограничение
решения (см. report.md, раздел ограничений).

## 3. Тесты пайплайна (`test_pipeline.py`)

- все 4 конфигурации обучаются на синтетической фикстуре и достигают macro-F1 > 0.9
  (baseline — исключение, он обязан предсказывать самый частый класс);
- сохранение/загрузка `joblib` не меняет предсказания (roundtrip);
- инференс отклоняет пустой текст, поднимает ошибку при отсутствии артефакта.

## 4. Тесты API (`test_api.py`)

- `/health` отвечает 200 и отражает состояние модели;
- `/predict` возвращает 422 на пустой вход, 200 с queue при модели, 503 без модели;
- `/ready` возвращает 503 без артефакта (readiness-проверка);
- `/metrics` считает запросы и ошибки по классам статусов (422 учитывается);
- веб-демо `GET /` отдаёт страницу, которая обращается к `POST /predict`.

Всего 17 автотестов, все проходят.

## 5. Smoke-тест живого сервера (выполнен вручную, см. README)

- `/health` (живость процесса) и `/ready` (готовность модели, 503 без артефакта)
  — реализованы и проверены;
- сценарий: /ready → 2 предсказания → /metrics → 422 на пустом входе.
