# Model card: классификатор очередей IT-поддержки

## Описание модели

Учебная модель проекта «Сервис классификации обращений в поддержку»
предсказывает одну из 10 очередей по теме `subject` и тексту `body`.
Разработчики проекта: Шелест М., Иванова Ю., Буянов Е., Ишбулатова С.
Поддерживаемые языки — английский и немецкий (EN/DE).

| Свойство | Значение |
|---|---|
| Конфигурация | `tfidf_wordchar_svc_tuned` |
| Артефакт | [`artifacts/model.joblib`](../artifacts/model.joblib) |
| Метаданные | [`artifacts/model_metadata.json`](../artifacts/model_metadata.json) |
| Признаки | `CombinedTfidf`: словные 1–2-граммы и символьные 3–5-граммы (`char_wb`) |
| Классификатор | `LinearSVC`, `class_weight="balanced"`, `random_state=42` |
| Подбор параметров | `GridSearchCV(cv=3)` только на train; сетка `C`: 1, 5, 10, 20 |
| Выбор конфигурации | По macro-F1 на validation из 5 экспериментов |
| Вероятности | Не калиброваны; API возвращает `confidence: null` |

Векторизаторы и классификатор сохраняются вместе. Перед векторизацией
поля очищаются от пробелов по краям и объединяются через перевод строки;
пропущенная тема в обучающих данных заменяется пустой строкой.
Колонки `answer`, `type`, `priority`, `tag_*` в признаки не входят.

## Назначение и область применения

Модель предназначена для учебного демо и предложения очереди оператору
с последующим подтверждением человеком. API возвращает рекомендацию,
но не создаёт тикет и не выполняет реальную маршрутизацию.

Классы: Billing and Payments, Customer Service, General Inquiry,
Human Resources, IT Support, Product Support, Returns and Exchanges,
Sales and Pre-Sales, Service Outages and Maintenance, Technical Support.

Пригодность для полностью автоматической маршрутизации реальных обращений
не подтверждена. Модель не предназначена для русского и других языков
за пределами EN/DE, определения срочности или генерации ответа клиенту.
Класса «доступ к курсу» в обучающих данных нет.

## Данные и обучение

Источник согласно [манифесту данных](../data/manifest.json): Customer IT
Support - Ticket Dataset, Tobias Bueck, Kaggle, версия 10, CC BY 4.0.
Корпус синтетический, содержит 28 587 обращений: 16 338 EN и 12 249 DE.
У 3 838 обращений отсутствует тема. Классы несбалансированы:
от 405 примеров General Inquiry до 8 362 Technical Support.

SHA256 исходного CSV:

```text
f187c090e59581c2bbf3aa1377c8db4dd647464ecf2ae51bf8966e42e0ed6bc0
```

Стратификация выполняется по `queue`, seed=42; индексы сохранены
в [`experiments/splits.json`](../experiments/splits.json).

| Выборка | Обращений | Использование |
|---|---:|---|
| Train | 20 010 | Обучение признаков и классификатора, подбор C через CV |
| Validation | 4 288 | Сравнение конфигураций |
| Test | 4 289 | Финальная оценка после выбора модели |

Согласно [аудиту данных](../experiments/data_validation.json), точных
текстовых пересечений между выборками нет. Одна пара train/test совпадает
после нормализации регистра и пробелов; близкие дубликаты аудит не исключает.

Источники: [результаты экспериментов](../experiments/results.csv),

интервалы не измерены.

## Ограничения и риски

- Синтетические тексты могут отличаться от реальных по лексике и структуре;
  перенос приведённых метрик на реальные обращения не доказан.
- Очереди поддержки семантически пересекаются. Ошибка рекомендации может
  вызвать повторное перенаправление и увеличить время ответа.
- Качество на немецком ниже, чем на английском. Перед внедрением нужно
  отдельно оценивать ошибки и задержки для каждой языковой группы;
  качество по другим группам пользователей не исследовано.
- У LinearSVC нет калиброванных вероятностей; порог уверенности для передачи
  обращения оператору не реализован. Успешный ответ API не гарантирует
  правильность очереди.
- Проверка кириллицы не определяет язык: неподдерживаемый язык на латинице
  может получить рекомендацию. Наличие известных признаков также не
  гарантирует, что обращение относится к области применения модели.
- Новые продукты и изменения очередей могут снижать качество; требуется
  оценка на свежих размеченных данных.

## Использование и сопровождение

`POST /predict` принимает тему до 300 символов и текст до 20 000 символов.
Хотя бы одно поле должно содержать непустой текст. Пустой ввод, превышение
лимитов, кириллица и нулевой вектор признаков приводят к HTTP 422 без назначения
очереди; при отсутствии загруженной модели возвращается HTTP 503.
Подробности — в [контракте API](api.md).

Перед реальным применением необходим пилот с подтверждением оператора
и измерением качества по языкам и очередям. Для сопровождения предусмотрены
технические счётчики `/metrics`; оценку macro-F1 на новой ручной разметке
и контроль дрейфа нужно организовать отдельно. План описан в
[документе о деплое и мониторинге](deployment_monitoring.md).

Воспроизводимость обеспечивают `uv.lock`, хэш данных, сохранённые индексы
выборок и [код экспериментов](../src/ticket_router/experiments.py).
Команды из корня репозитория:

```bash
uv sync --locked
uv run python scripts/download_data.py
uv run python scripts/evaluate_model.py
```

Последняя команда проверяет сохранённую модель без повторного обучения.
Для воспроизведения обучения: `uv run ticket-router-train`; команда
перезаписывает артефакт и результаты экспериментов. Test нельзя использовать
для настройки новых конфигураций. Файлы `joblib` следует загружать только
из доверенного источника.
