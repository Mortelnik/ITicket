# Контракт API

Базовый URL: `http://localhost:8000`. Модель рекомендует одну из 10 очередей
IT-поддержки для обращений на английском или немецком. Это учебная рекомендация:
реальный тикет, очередь сообщений и подключение оператора не создаются.

## GET /

Демо использует тот же `POST /predict`, содержит три готовых примера EN и
предупреждение об ограничениях. Русский язык не поддерживается.

## Защита от частых запросов и сканирования секретов

До обработки маршрута API проверяет URL для любого HTTP-метода. Запросы
к `.env*`, `.git*`, `.aws*`, `.ssh*`, `.kube*`, `.netrc`, `.npmrc`, `.pypirc`,
`.dockercfg`, `.docker`, `credentials*`, `secrets*`, приватным ключам,
`config.php`, `wp-config.php` и их указанным в фильтре резервным копиям
получают **444 с пустым телом**. Учитываются вложенные пути, регистр,
обратные слеши и повторное URL-кодирование. Фильтр проверяет путь, а не текст
обращения. Это HTTP-статус приложения; закрытие соединения без HTTP-ответа,
как у nginx `return 444`, здесь не реализовано.

Остальные запросы ограничены скользящим окном: **60 запросов за 60 секунд
на IP**, включая демо, неизвестные маршруты, проверки здоровья и метрики.
При превышении возвращается **429** с JSON `detail` и заголовком
`Retry-After` (секунды до освобождения квоты). Отказы не запускают инференс.
Фильтр секретов имеет приоритет и возвращает 444 даже при исчерпанной квоте.

Настройки задаются переменными окружения до запуска процесса:

| Переменная | По умолчанию | Назначение |
|---|---:|---|
| `TICKET_ROUTER_RATE_LIMIT` | 60 | Число запросов в окне на один IP |
| `TICKET_ROUTER_RATE_WINDOW` | 60 | Длина окна в секундах |
| `TICKET_ROUTER_RATE_MAX_CLIENTS` | 10000 | Максимум активных IP в памяти |

Все значения — положительные целые. При заполнении таблицы IP новые клиенты
получают 429 до освобождения места; активные квоты не вытесняются. Состояние
локально для процесса и сбрасывается при перезапуске. Для нескольких workers
или реплик нужен общий ограничитель на reverse proxy либо общее хранилище.

IP берётся из ASGI `request.client`, заголовки клиента middleware не читает.
Для прямого доступа запускайте Uvicorn с `--no-proxy-headers` (так настроен
Docker). За reverse proxy включайте `--proxy-headers` с
`--forwarded-allow-ips`, содержащим только адреса доверенных прокси;
прокси должен перезаписывать входящие заголовки адреса клиента.

## POST /predict

Оба поля — строки; по отдельности необязательны (по умолчанию пустые).
Хотя бы одно поле должно содержать непробельный текст.
Лимиты: `subject` — 300 символов, `body` — 20 000 символов.

Запрос:

```json
{"subject": "Login failed", "body": "Cannot log into my account, error 500"}
```

Ответ 200:

```json
{"queue": "IT Support", "confidence": null}
```

`confidence` заполняется только для вероятностных моделей. Выбранная
LinearSVC не выдаёт вероятность, поэтому значение равно `null`.

Ошибки:

- `422` — пустой текст, неверный тип поля или превышение лимита;
- `422` — есть кириллица или TF-IDF не распознал ни одного признака;
- `503` — модель не загружена;
- `500` — внутренняя ошибка; учитывается в `errors_5xx`.

При отказе ответ содержит `detail`, без `queue`. Валидация схемы возвращает
список ошибок в `detail`, проверка текста — строку. Отказ не является
предсказанием. Клиент должен предложить операторскую обработку, а не назначать
очередь самостоятельно. Проверка кириллицы не определяет все языки: для
неподдерживаемых языков на латинице корректный отказ не гарантируется.

## GET /health

Живость процесса, HTTP 200:

```json
{"status": "ok", "model_loaded": true, "version": "0.1.0", "uptime_seconds": 3.6}
```

Используется для liveness. При отсутствии модели процесс может быть жив,
но не готов к классификации.

## GET /ready

HTTP 200 с `{"status": "ready"}`, если модель загружена; иначе HTTP 503.
Используется Docker HEALTHCHECK и планируемой readiness-пробой Kubernetes.
Повреждённый или несовместимый артефакт останавливает старт приложения.

## GET /metrics

JSON с полями:

| Поле | Значение |
|---|---|
| requests_total | Все входящие HTTP-запросы, включая проверки здоровья и метрики |
| errors_4xx / errors_5xx | Ответы соответствующего класса; необработанные исключения тоже считаются |
| error_rate | (4xx + 5xx) / requests_total |
| predictions_total | Успешные классификации |
| predicted_queues | Счётчики успешных предсказаний по очередям |
| rejected_inputs_total | Ответы 422 на /predict, включая ошибки схемы и лимитов |
| unsupported_texts_total | Отказы из-за кириллицы или нулевого вектора признаков |
| secret_requests_total | Запросы к секретам, отклонённые с 444 |
| rate_limited_requests_total | Запросы, отклонённые с 429 |
| latency_sample_size | Число завершённых измерений, до 1000 |
| latency_p95_ms | p95 последних до 1000 запросов до формирования заголовков ответа; null до первого измерения |

Счётчики защищены от одновременных обновлений потоками. Метрики локальны для
одного процесса, сбрасываются при его перезапуске и не агрегируются между
workers/репликами. Текущий запрос /metrics ещё не входит в завершённые измерения.
Это учебный JSON, не формат экспозиции Prometheus.

## CLI и путь к модели

```bash
uv run ticket-router "Login failed" "Cannot log into my account, error 500"
```

По умолчанию артефакт ищется относительно рабочего каталога:
`artifacts/model.joblib`. Для запуска из другого каталога задайте абсолютный
путь через `TICKET_ROUTER_MODEL_PATH`. В Docker он задан явно.
Загружайте только доверенные joblib-артефакты совместимой версии зависимостей.
