Система получает тему и текст обращения и предлагает одну из 10 очередей
IT-поддержки: оплата, техническая поддержка, возвраты и другие. Бизнес-цель —
сократить ручную первичную сортировку; ошибочная очередь означает повторное
перенаправление и задержку ответа. Изменение времени обработки и экономия
операторов пока не измерены.

Это учебная имитация маршрутизации: API возвращает `queue`, а не создаёт
реальный тикет и не подключает оператора. Поддерживаются **только EN/DE**.
Класс «доступ к курсу» в выбранном датасете отсутствует: это адаптация кейса
к IT-поддержке, а не классификатор обращений образовательной платформы.

**Результат:** test macro-F1 = **0.6185** (baseline на val — 0.0453), 10 классов,
языки EN/DE. Решение — скромное по качеству, но честное: данные синтетические,
классы пересекаются семантически (подробности — в отчёте). Есть веб-демо
с имитацией чата (подход заимствован у проекта коллег).

Воспроизводимость: метрики в README и в experiments/ получены на одном фиксированном split (seed=42), версия данных закреплена sha256 в data/manifest.json, версии зависимостей — в uv.lock. Повторный прогон ticket-router-train на тех же данных должен давать те же цифры; расхождение — сигнал об изменении окружения или данных.

## Быстрый старт

```bash
# Python 3.12, uv; команды выполняются из корня репозитория.
# 1. Зависимости (воспроизводимо из uv.lock)
uv sync --locked

# 2. Данные (28 587 тикетов, проверка sha256)
uv run python scripts/download_data.py

# 3. Обучение и сравнение 5 конфигураций (несколько минут на CPU)
uv run ticket-router-train

# 4. Тесты
uv run pytest -q

# 5. Сервис (веб-демо откроется на http://localhost:8000/)
uv run uvicorn ticket_router.api:app --port 8000 --no-proxy-headers
curl -X POST localhost:8000/predict -H 'Content-Type: application/json' \
  -d '{"subject":"Login failed","body":"Cannot log into my account, error 500"}'
# → {"queue":"IT Support","confidence":null}

# CLI-вариант
uv run ticket-router "Login failed" "Cannot log into my account, error 500"
```

Минимальный сценарий проверки без обучения: uv sync --locked → uv run pytest -q → uv run uvicorn ticket_router.api:app --port 8000 → uv run python scripts/smoke_api.py --url http://127.0.0.1:8000. Этого достаточно, чтобы убедиться, что артефакт из репозитория грузится и API отвечает; шаги с CSV и обучением нужны только для переобучения или аудита данных.

Артефакт `artifacts/model.joblib` уже в репозитории — шаги 2–3 можно пропустить
и сразу запускать API и тесты.

После запуска откройте `http://localhost:8000/` и выберите примеры входа,
оплаты и возврата. Русский текст и текст без известных признаков возвращают
422 с объяснением, очередь им не назначается. Вероятность ответа LinearSVC
не вычисляется (`confidence: null`). Ошибки классификации всё ещё возможны.

Проверка данных и метрик без повторного обучения (нужен скачанный CSV):

```bash
uv run python scripts/check_data.py --output experiments/data_validation.json
uv run python scripts/evaluate_model.py --output experiments/artifact_validation.json
uv run python scripts/smoke_api.py --url http://127.0.0.1:8000
```

Последняя команда требует уже работающего API. Первая проверяет хэш, схему,
покрытие и непересечение индексов, точные и нормализованные совпадения текстов.
Вторая сверяет метрики выбранного артефакта с метаданными; не используйте test
для настройки новой модели.

## Docker

Запустите Docker Engine или Docker Desktop с Linux-контейнерами.
Эти команды подходят для PowerShell и bash:

```bash
docker build -t iticket:local .
docker run -d --name iticket --restart unless-stopped -p 127.0.0.1:8000:8000 iticket:local
docker logs -f iticket
```

Откройте `http://localhost:8000/` (демо) или `http://localhost:8000/docs`
(API). Модель входит в образ; обучение и CSV для контейнера не нужны.
Healthcheck проверяет `/ready`. Контейнер работает от непривилегированного
пользователя. Для другой модели задайте `TICKET_ROUTER_MODEL_PATH` и подключите
доверенный артефакт соответствующей версии зависимостей.

```bash
docker stop iticket
docker rm iticket
```

После изменения кода или модели пересоберите образ и пересоздайте контейнер.
Проверка сервиса: `uv run python scripts/smoke_api.py`. В CI добавлены сборка
образа и проверка API внутри контейнера. **Локальная сборка пока не подтверждена:**
на 13.11.2026 Docker Engine в среде проверки недоступен. Наличие workflow
не означает, что удалённый CI уже прошёл.

## Эксперименты (фиксированный split 70/15/15, seed=42)

| Эксперимент | val macro-F1 | test macro-F1 |
|---|---|---|
| DummyClassifier (baseline) | 0.045 | — |
| TF-IDF слова + LogisticRegression | 0.469 | — |
| TF-IDF слова+символы + LogisticRegression | 0.491 | — |
| TF-IDF слова+символы + LinearSVC | 0.604 | — |
| **+ GridSearchCV(cv=3) по C, лучший C=10** | **0.619** | **0.619** |

Качество по языкам (test): EN 0.702, DE 0.492. Подробные метрики по классам и
матрица ошибок — в `experiments/`.

## Ключевые решения

- признаки — только `subject` + `body`: колонки `answer/type/priority/tag_*`
  недоступны в момент маршрутизации (исключена утечка данных);
- единый sklearn-pipeline сохраняется одним артефактом (предобработка и модель
  не расходятся между обучением и инференсом);
- выбор модели по val, тест — один раз после выбора;
- `class_weight="balanced"` из-за дисбаланса классов (8362 vs 405);
- основной критерий — macro-F1 (равное внимание редким очередям).

## Ограничения (кратко)

Датасет синтетический; классы поддержки семантически пересекаются (Technical vs
Product vs IT Support дают основную массу ошибок); качество на немецком заметно
ниже; модель не калибрована (LinearSVC без вероятностей). Проверка кириллицы
не является универсальным определителем языка: другой неподдерживаемый язык
на латинице может получить очередь. Есть одна пара нормализованных совпадений
между train/test; точных совпадений нет. API ограничивает тему 300 символами,
текст 20 000: из 4 289 тестовых обращений 2 не проходят лимит длины. Полный список — в
[отчёте](docs/report.md).
